1. CURRENT STATE
================================================================================

What's live right now (11 routes):

  /            Home (landing with hero, CTAs, architecture overview)
  /dashboard   9-section synthetic tick lakehouse (overview, datasets, explorer,
               pipelines, ticks, models, alerts, governance, incidents)
  /markets     Live crypto (CoinGecko) + FX (Frankfurter) + synthetic equities
  /news        RSS feeds from 10 financial + tech sources (CNBC, BBC, NPR,
               WSJ, Yahoo Finance, Investing.com, FT, TechCrunch, Verge, HN)
  /files       Drag-drop upload, CSV/JSON/image preview, CSV export
  /automate    Mock rule builder + scheduled jobs
  /pricing     7-provider free-tier usage tracking + upgrade prompts
  /settings    API key management (localStorage), theme, data source toggles
  /about       Project info + GDPR privacy notice
  /docs        Quick reference + customization guide
  /login       Mock auth form (no credentials transmitted)

Architecture:
  - Next.js 16 App Router (MPA, not SPA)
  - TypeScript 5, Tailwind CSS 4, shadcn/ui (73 components)
  - Prisma + SQLite (15 models, synthetic seed: ~13K ticks, ~5K OHLCV bars)
  - Zustand store (auth, API keys, usage tracking — all localStorage-persisted)
  - Dual-mode deployment: standalone (dev) or static export (GitHub Pages)
  - Provider registry pattern (src/lib/data-sources.ts) — add a provider by
    adding one object to an array; Pricing + Settings pages auto-update
  - Static fallback data (src/lib/static-fallback.ts) — renders synthetic
    data when API routes unavailable on GitHub Pages

Stats:
  - ~12,153 lines of TypeScript/TSX
  - 11 routes, 73 components, 16 API routes (private repo)
  - 7 data providers integrated (3 active, 4 ready to activate with API keys)
  - 10 RSS sources (7 financial, 3 tech)
  - Both repos on GitHub, public preview deployed via GitHub Actions

#4  "DATA STORIES" — AUTO-GENERATED NARRATIVE BRIEF (THE CREATIVE FEATURE)
────────────────────────────────────────────────────────────────────────────────

What it unlocks:
  - A "morning brief" that reads the dashboard and writes a 200-word summary
  - Anomaly detection (statistical, no ML needed)
  - Trend analysis ("AAPL up 3.2% — largest gain in 14 days")
  - Correlation discovery ("BTC and ETH moved together r=0.94")
  - Plain-English explanations of chart patterns
  - Voice-readable (for accessibility / hands-free use)

Why it's novel:
  - Most dashboards show data; this one EXPLAINS it
  - No LLM dependency — pure template-based narrative generation
  - Runs entirely client-side (works on GitHub Pages)
  - Updates as data changes (live re-generation)
  - Different "voice" modes: executive brief, analyst notes, compliance log

Implementation:
  src/lib/story-engine/
    patterns.ts       # pattern matchers (spike, trend, correlation, anomaly)
    narrative.ts      # template-based natural language generation
    brief-builder.ts  # assembles sections into a coherent brief
    voices.ts         # executive / analyst / compliance voice presets

  src/app/(app)/stories/page.tsx   # the Stories page
  src/components/stories/
    BriefCard.tsx     # renders a generated brief
    PatternCard.tsx   # shows detected patterns
    TimelineEvent.tsx # narrative timeline of detected events

Effort: ~6 hours
Dependencies: None (works with synthetic fallback data)

Story patterns to detect:
  1. SPIKE     — value exceeds 2 standard deviations from rolling mean
  2. TREND     — monotonic change over N periods (up or down)
  3. CORRELATION — two series move together (Pearson r > 0.7)
  4. REGIME CHANGE — volatility shifts by >50%
  5. ANOMALY   — value outside historical min/max range
  6. CLUSTER   — multiple alerts fire in same time window
  7. RECOVERY  — system returns to normal after incident
  8. DEGRADATION — gradual decline over multiple periods

Voice presets:
  EXECUTIVE:  "Q3 revenue grew 12% to $4.2M, driven by a 3.2% gain in AAPL..."
  ANALYST:    "Detected spike in ticks.normalized at 14:06 UTC. Magnitude: 2.3σ..."
  COMPLIANCE: "Audit log shows 3 denied access attempts in the last 24h..."

3. THE "DATA STORIES" FEATURE (detailed design)
================================================================================

This is the creative centerpiece — the thing that makes this template different
from every other dashboard template out there.

CONCEPT
───────
Most dashboards show you data and expect you to interpret it. Data Stories
reads the data for you and writes a plain-English narrative of what's happening.
Think of it as an automated analyst that writes a morning brief.

The key insight: you don't need an LLM to generate useful narratives. Most
analyst commentary follows predictable patterns:
  - "X rose by Y% to Z, the largest gain since [date]"
  - "Alert A fired at [time], caused by [pattern]"
  - "Series X and Y are correlated (r=0.94) over the last N periods"

These patterns can be detected statistically and rendered as natural language
with simple templates. No API calls, no latency, no cost.

DETECTED PATTERNS
─────────────────
1. SPIKE         — value > 2σ from rolling mean
2. TREND         — monotonic change over N+ periods
3. CORRELATION   — Pearson r > 0.7 between two series
4. REGIME_CHANGE — volatility shifts by >50%
5. ANOMALY       — value outside historical min/max
6. CLUSTER       — multiple alerts in same time window
7. RECOVERY      — system returns to normal after incident
8. DEGRADATION   — gradual decline over multiple periods

VOICE PRESETS
─────────────
EXECUTIVE:    High-level, dollar amounts, percentages, business impact
              "Q3 revenue grew 12% to $4.2M, driven by..."

ANALYST:      Technical, precise, timestamps, statistical measures
              "Detected spike in ticks.normalized at 14:06 UTC.
               Magnitude: 2.3σ above rolling 1h mean..."

COMPLIANCE:   Formal, audit-focused, actor/action/resource
              "Audit log shows 3 denied access attempts in the last 24h.
               Actor: research@. Resources: ticks.normalized, ohlcv.1m..."

BRIEF STRUCTURE
───────────────
1. HEADLINE (1 sentence summary of the most important thing)
2. KEY METRICS (3-5 bullets of notable numbers)
3. PATTERNS DETECTED (list of patterns with evidence)
4. ALERTS (active alerts with context)
5. RECOMMENDED ACTIONS (template-based, tied to patterns)

Example output:
──────────────
HEADLINE: Tier-1 SLO budget at 38% — on track to exhaust in 18 days
at current burn rate.

KEY METRICS:
  • 100B events ingested today (within normal range)
  • p99 latency: 217ms (below 250ms SLO ceiling)
  • 2 active alerts (1 critical, 1 warning)
  • Aggregate pipeline lag: 305ms (degraded, investigate)

PATTERNS DETECTED:
  • SPIKE: Aggregate checkpoint duration exceeded 2σ at 14:02 UTC
  • CORRELATION: AAPL and MSFT moved together (r=0.91) over last 24h
  • DEGRADATION: Aggregate pipeline lag trending up over 6h (+47%)

ACTIVE ALERTS:
  • CRITICAL: Aggregate checkpoint > 60s (firing 3m ago)
  • WARNING: Manifest lock contention (firing 8m ago)

RECOMMENDED ACTIONS:
  1. Investigate Aggregate pipeline checkpoint storm (see incident: April 2024)
  2. Review compaction service backpressure configuration
  3. Consider pausing non-critical feature deploys until SLO recovers

4. PLUGIN ARCHITECTURE (detailed design)
================================================================================

GOAL
────
Make the template extensible without touching core files. A plugin is a
self-contained folder that adds a page, nav entry, and optional API routes.

STRUCTURE
─────────
src/plugins/
  weather/
    plugin.json        # metadata
    page.tsx           # the page (default export)
    api/
      forecast.ts      # optional API routes
    components/
      WeatherCard.tsx  # plugin-specific components
    README.md          # plugin docs

  flights/
    plugin.json
    page.tsx
    api/
      opensky.ts
    README.md

plugin.json SCHEMA
───────────────────
{
  "name": "weather",                    // unique identifier (kebab-case)
  "title": "Weather",                   // display name
  "description": "NOAA + OpenWeather data",
  "icon": "cloud",                      // lucide-react icon name
  "category": "environmental",          // for grouping in sidebar
  "navOrder": 5,                        // sort order in sidebar
  "requiredRole": "demo",               // minimum role to access
  "dataSources": ["noaa", "openweather"], // providers this plugin uses
  "version": "1.0.0",
  "author": "MERIDIAN Team",
  "homepage": "https://github.com/...",
  "enabled": true                      // can be toggled in Settings
}

AUTO-DISCOVERY
──────────────
At build time, a script scans src/plugins/*/plugin.json and generates:
  - src/lib/plugins-registry.ts (auto-generated, do not edit)
  - Sidebar entries (sorted by navOrder, filtered by role)
  - Route handlers (/plugins/<name>)
  - Search index entries
  - Settings page toggles (enable/disable per plugin)

This means adding a new page to the template is:
  1. Create src/plugins/<name>/plugin.json
  2. Create src/plugins/<name>/page.tsx
  3. Rebuild — done. Nav, search, routes all auto-wired.

5. ROLE-BASED ACCESS (demo / admin / enterprise)
================================================================================

THREE TIERS
──────────

DEMO (default, no login required):
  - View all dashboards (read-only)
  - View live markets data
  - View news feeds
  - Export data as CSV/JSON
  - View pricing/limits
  - Cannot: upload files, manage API keys, view audit log, configure sources

ADMIN (login required):
  - Everything demo can do, plus:
  - Upload files
  - Manage API keys (Settings page)
  - Configure data sources
  - View audit log
  - Manage saved dashboards
  - Configure automation rules

ENTERPRISE (license key required):
  - Everything admin can do, plus:
  - Manage users (invite, revoke, assign roles)
  - Custom plugins (install third-party plugins)
  - SSO (SAML/OIDC)
  - Audit log export (compliance)
  - Custom branding (logo, colors, domain)

LOGIN
─────
Demo account:     demo@meridian.template / demo
Admin account:    admin@meridian.template / admin

These are mock credentials (no backend). In production with #1 (NextAuth),
these would be real GitHub OAuth accounts with role assignments.

The login form will have a "Quick demo login" button that auto-fills demo
credentials, and an "Admin login" toggle that reveals the admin field.
